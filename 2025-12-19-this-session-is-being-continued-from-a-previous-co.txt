  Summary of Fixes                                                               
                                                                                 
  The issue was with the SQL queries using template variables. When using multi-value Grafana template variables in ClickHouse queries, the pattern ServiceName IN ($service) fails when the variable is empty or when "All" is selected (creates invalid IN tuple() SQL).
                                                                                 
  Solution Applied                                                               
                                                                                 
  Used the Grafana ClickHouse datasource's $__conditionalAll macro which:        
  - Replaces the condition with 1=1 (pass-through) when "All" is selected        
  - Uses the actual filter when specific values are selected                     
                                                                                 
  Before:                                                                        
  WHERE $__timeFilter(Timestamp)                                                 
    AND ServiceName IN ($service)                                                
                                                                                 
  After:                                                                         
  WHERE $__timeFilter(Timestamp)                                                 
    AND $__conditionalAll(ServiceName IN ($service), $service)

  The OTEL Collector sends data directly to ClickHouse (not through Kubernetes API). The flow is:
                                                                                 
  1. Applications send telemetry to OTEL Collector via OTLP protocol             
  2. OTEL Collector processes and exports to ClickHouse via native TCP protocol (port 9000)
  3. Grafana queries ClickHouse to visualize the data
